# Реестр возможностей и проверок

## Dev Container Feature

`NVIM-DEVCONTAINER-001`: CI собирает OCI Feature с Neovim и точным Git-снимком
runtime-конфига, проверяет lifecycle и публикует успешный `v5` в
`ghcr.io/emergy/astronvim/astronvim:1`. Конфиг ставится от remote user;
существующий конфиг и локальные правки сохраняются. Состояние: реализовано;
успешная публикация подтверждается конкретным Actions run.
Настройка: `.github/workflows/devcontainer-feature.yml`, `devcontainer/features/astronvim`,
`scripts/package_devcontainer_feature.py`; описание — [CI и GHCR](devcontainer-feature.md).
Платформы: Linux glibc amd64/arm64 в контейнере, хост WSL/Linux/macOS.
Зависимости: Docker, GitHub Actions, GHCR и системные пакеты из README feature.
Новых клавиш/переводов раскладки нет. Автотесты:
`python3 -m unittest discover -s tests/devcontainer_feature -v`; Docker-команды
приведены в документации. Smoke не загружает пользовательский init и не ставит
плагины. UI и ARM64 требуют отдельного результата проверки.

Реестр наполняется по мере инвентаризации и изменений. Ниже перечислены
возможности, для которых уже оформлена запись; это пока не полный список сборки.
Описание профилей: [универсальная конфигурация](universal.md).

## Справка по сочетаниям клавиш

| ID | Возможность и ожидаемое поведение | Состояние | Настройка |
|---|---|---|---|
| NVIM-HELP-001 | Which-key показывает основные привязки, скрывает русские дубли и служебные записи `LM (`. Самим привязкам разрешено работать. | Включено | `lua/plugins/which-key.lua`, `lua/keymap_help.lua` |
| NVIM-HELP-002 | Справка `?` в Snacks Picker, для списка и поля ввода, скрывает те же дубли. Сохраняются английские действия, колонки и закрытие справки вместе с поиском. | Включено | `lua/plugins/snacks.lua`, `lua/keymap_help.lua` |

Область: все профили конфигурации, включая WSL/Linux, devcontainers, macOS,
Termux и Termux:Launcher. Зависимости: закреплённые which-key, Snacks и
langmapper; настройки раскладки — `lua/plugins/langmapper.lua`. Сочетания
содержат русские и английские варианты; фильтрация применяется только к справке.
Передача клавиш терминалом не меняется.

Автоматическая проверка обеих записей:

```sh
nvim --headless -u NONE -i NONE -l tests/check_picker_help.lua
```

Тест открывает настоящий Picker и справку списка/ввода, проверяет фильтрацию,
сохранение исходных карт, английских действий и закрытие окон. Проверен локально
на WSL, Neovim 0.11.5. Остальные платформы для этой правки отдельно не проверены.
Версия коммита и результат записываются в `.reports/picker-help.json`.

Ручная проверка NVIM-HELP-002: открыть `Пробел f w`, перейти к списку и нажать
`?`. Проверить отсутствие русских дублей и `LM (`; повторное `?` должно закрыть
справку. Проверить, что русские привязки поиска продолжают работать.
Автотест не заменяет проверку фактического ввода с русской раскладкой в GUI.

## Команды оболочки

### Интеграция Bash в Nterm

`NTERM-AUTO-001`: автозапуск Nterm в каждой новой сессии телефона через
`terminal/autostart.bash`; декларативная точка подключения —
`nix/launcher/bashrc`, нативный Termux — подключение из его `.bashrc`.
После выхода доступен Bash. SSH, вложенные оболочки, Neovim, tmux/screen,
неинтерактивный запуск и отсутствие TTY исключены. `NTERM_AUTOSTART=0`
отключает автозапуск. Зависимости: Bash и команда `nterm` в PATH.
Платформы включения: нативный Termux и Nix-on-Droid / Launcher; WSL/Linux
используется для изолированной проверки, в его `.bashrc` включение не добавляется.
Сочетаний клавиш и переводов русской раскладки эта возможность не меняет.
Автотест: `python3 tests/check_nterm_autostart.py`; интеграция с настоящим
профилем — `python3 tests/check_nterm.py`. Ручной сценарий: создать две
новые сессии приложения, в каждой увидеть Nterm; закрыть его и получить Bash;
подключиться по SSH и получить Bash. Физический интерфейс приложения
автотестом не проверяется. Результаты: `.reports/nterm-autostart.json`.

`NTERM-BASH-001`: включена в лёгком профиле `nterm`. Настройка
`terminal/bashrc` устанавливает обработчики редактирования и выполнения
команды в Readline-картах `emacs-standard`, `vi-insert`, `vi-command`
без ошибок при запуске. Описание: [Nterm](nterm.md).
Платформы: WSL/Linux, нативный Termux и Nix-on-Droid; зависимости — Bash,
Neovim и установленный профиль. macOS этой проверкой не охвачена.
Раскладка не влияет на управляющие байты: `Ctrl+x Ctrl+e` вызывает редактор
текущей команды у локального Bash prompt; во вложенном приложении сочетание
проходит внутрь. Внутренние Readline-последовательности выполнения черновика
описаны в `terminal/bashrc`, отдельных пользовательских клавиш не добавлено.

Проверка: `python3 tests/check_nterm.py` — настоящий PTY, отсутствие ошибки
`invalid keymap name`, обработчики в трёх картах, редактирование команды,
выполнение в том же Bash и прохождение клавиш во вложенный Neovim.
Это не проверка физической мобильной клавиатуры или её жестов.
Результаты исправления: `.reports/nterm-readline-fix-wsl.log`,
`.reports/nterm-readline-fix-termux.log`, `.reports/nterm-readline-fix-nix.log`.

## NTERM-YANK-001 — подсветка скопированного текста

Включена в nterm: после `y`/`yy` в Normal или `y` по Visual-выделению
скопированный фрагмент подсвечивается группой `IncSearch` на 150 мс,
как в AstroNvim. Используется встроенный `vim.hl.on_yank()` с совместимостью
`vim.highlight.on_yank()`, без загрузки плагинов. OSC52-копирование сохраняется.
Вставка и удаление этот эффект не вызывают; дополнительные клавиши не назначены.
Настройка: `lua/terminal_profile.lua`, событие `TextYankPost`.
Платформы: все профили nterm при поддержке встроенной функции Neovim.
Проверка: `python3 tests/check_nterm.py` — настоящее копирование из терминального
буфера в PTY, наличие подсветки сразу после `yy`, её исчезновение и вывод OSC52.
Проверка на WSL/Linux не подтверждает внешний вид на macOS/Android.

## LAUNCHER-KEYBOARD-001 — жесты раскладки и истории буфера

Включены симметрично в английской и русской экранных раскладках Launcher:
`Ctrl ↙` переключает на предыдущую раскладку (при двух — EN/RU),
`Shift ↙` открывает историю буфера обмена. Основные нажатия Ctrl/Shift сохранены.
Файлы: `nix/launcher/keyboard-layout.xml`, `keyboard-layout-ru.xml`.
Платформа: Termux:Launcher; зависимость — встроенная клавиатура приложения.
Проверка: `python3 tests/check_launcher_keyboard.py` — оба жеста и симметрия
обеих раскладок. Ручной сценарий после установки XML: свайп Ctrl вниз-влево
меняет EN/RU, свайп Shift вниз-влево открывает историю буфера. Физический
интерфейс телефона локальным XML-тестом не проверяется.

## NTERM-CWD-001 — каталог Bash на macOS и Linux

Включено: при каждом приглашении локальный Bash сообщает `$PWD` через OSC 777
с токеном текущей сессии. Nterm принимает только абсолютный существующий каталог
без управляющих символов. На Linux/Android сохранено чтение `/proc`; на macOS
оно не требуется. Новые панели наследуют актуальный каталог активной оболочки.
Файлы: `terminal/bashrc`, `lua/terminal_profile.lua`; новых сочетаний нет.
Зависимости macOS: современный Bash из PATH (проверено Homebrew Bash 5.3), Neovim.
Проверка: `python3 tests/check_nterm.py` — настоящий PTY, `cd`, редактирование и
выполнение команды в той же оболочке, проверка каталога; временный путь теста
канонизируется для macOS `/tmp` → `/private/tmp`. Физический GUI не проверяется.
