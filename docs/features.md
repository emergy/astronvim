# Реестр возможностей и проверок

Реестр наполняется по мере инвентаризации и изменений. Ниже перечислены
возможности, для которых уже оформлена запись; это пока не полный список сборки.
Описание профилей: [универсальная конфигурация](universal.md).

## Справка по сочетаниям клавиш

| ID | Возможность и ожидаемое поведение | Состояние | Настройка |
|---|---|---|---|
| NVIM-HELP-001 | Which-key показывает основные привязки, скрывает русские дубли и служебные записи `LM (`. Самим привязкам разрешено работать. | Включено | `lua/plugins/which-key.lua`, `lua/keymap_help.lua` |
| NVIM-HELP-002 | Справка `?` в Snacks Picker, для списка и поля ввода, скрывает те же дубли. Сохраняются английские действия, колонки и закрытие справки вместе с поиском. | Включено | `lua/plugins/snacks.lua`, `lua/keymap_help.lua` |

Область: все профили конфигурации, включая WSL/Linux, devcontainers, macOS,
Termux и Termux:Launcher. Зависимости: закреплённые which-key, Snacks и
langmapper; настройки раскладки — `lua/plugins/langmapper.lua`. Сочетания
содержат русские и английские варианты; фильтрация применяется только к справке.
Передача клавиш терминалом не меняется.

Автоматическая проверка обеих записей:

```sh
nvim --headless -u NONE -i NONE -l tests/check_picker_help.lua
```

Тест открывает настоящий Picker и справку списка/ввода, проверяет фильтрацию,
сохранение исходных карт, английских действий и закрытие окон. Проверен локально
на WSL, Neovim 0.11.5. Остальные платформы для этой правки отдельно не проверены.
Версия коммита и результат записываются в `.reports/picker-help.json`.

Ручная проверка NVIM-HELP-002: открыть `Пробел f w`, перейти к списку и нажать
`?`. Проверить отсутствие русских дублей и `LM (`; повторное `?` должно закрыть
справку. Проверить, что русские привязки поиска продолжают работать.
Автотест не заменяет проверку фактического ввода с русской раскладкой в GUI.

|---|---|---|---|

| NVIM-EMBED-002 | `/* yaml */ <<-EOT` выбирает язык HCL heredoc. Комментарий важнее имени маркера; после завершения возвращается HCL-подсветка. Область: все поддерживаемые профили. Зависимости: доступный runtime syntax

Новых сочетаний клавиш нет. Команды проверок:

```sh
nvim --headless -u NONE -i NONE -l tests/check_yaml_blocks.lua
nvim --headless -u NONE -i NONE -l tests/check_hcl_blocks.lua
nvim --headless -u NONE -i NONE -l tests/check_jinja_templates.lua
```

Проверки охватывают соседние языки, явный выбор и запасное поведение,
границы блоков, Jinja и редактирование меток. Результаты по версиям и платформам
для общего обработчика: `.reports/embedded-blocks.json`.

## Команды оболочки

### Интеграция Bash в Nterm

`NTERM-BASH-001`: включена в лёгком профиле `nterm`. Настройка
`terminal/bashrc` устанавливает обработчики редактирования и выполнения
команды в Readline-картах `emacs-standard`, `vi-insert`, `vi-command`
без ошибок при запуске. Описание: [Nterm](nterm.md).
Платформы: WSL/Linux, нативный Termux и Nix-on-Droid; зависимости — Bash,
Neovim и установленный профиль. macOS этой проверкой не охвачена.
Раскладка не влияет на управляющие байты: `Ctrl+x Ctrl+e` вызывает редактор
текущей команды у локального Bash prompt; во вложенном приложении сочетание
проходит внутрь. Внутренние Readline-последовательности выполнения черновика
описаны в `terminal/bashrc`, отдельных пользовательских клавиш не добавлено.

Проверка: `python3 tests/check_nterm.py` — настоящий PTY, отсутствие ошибки
`invalid keymap name`, обработчики в трёх картах, редактирование команды,
выполнение в том же Bash и прохождение клавиш во вложенный Neovim.
Это не проверка физической мобильной клавиатуры или её жестов.
Результаты исправления: `.reports/nterm-readline-fix-wsl.log`,
`.reports/nterm-readline-fix-termux.log`, `.reports/nterm-readline-fix-nix.log`.
