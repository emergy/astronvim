# Общая конфигурация Neovim для Linux и Termux

Один репозиторий сохраняет привычные сочетания, Neo-tree, Hop, терминалы,
панель Codex, сниппеты и обработку многострочного YAML. Основа — текущий
AstroNvim 5 и версии плагинов из `lazy-lock.json`. Переход на AstroNvim 6
не входит в эту работу.

## Профили

`lua/user_platform.lua` определяет Termux по `PREFIX` или `TERMUX_VERSION`.
Пути к языковым серверам находятся через `PATH`; абсолютных путей телефона
в конфигурации нет.

- Linux, WSL и devcontainers используют существующие интеграции Mason.
- Termux использует совместимые с Android системные инструменты и отдельный
  набор Node.js-инструментов. Mason и его автоматические установщики выключены.
- В Termux движок поиска blink.cmp работает на Lua. Устанавливать Rust или
  загружать готовую библиотеку для glibc не требуется.
- Дополнительные инструменты Termux находятся в каталоге данных Neovim:
  `tools/bin` и `tools/node_modules/.bin`. Они добавляются в `PATH` самого
  Neovim и его дочерних процессов, не меняя настройки оболочки.
- Панель Codex остаётся справа и занимает 33% ширины. В Termux автоматическая
  установка Codex через npm выключена: нужен работающий Android-бинарник.
- Список LSP в Termux формируется по реально установленным программам.
  Отсутствие необязательного сервера не мешает запуску редактора.

## Зависимости

Lua-конфигурация и lock-файл общие. Парсеры Tree-sitter, бинарные библиотеки,
Mason-пакеты и кэши устанавливаются отдельно для каждой ОС и архитектуры.
Нельзя переносить скомпилированные библиотеки WSL x86-64 в Android ARM64.

Node.js-инструменты зафиксированы в `tools/package.json` и
`tools/package-lock.json`. Этому набору требуется Node.js 26 или новее.
Он предназначен для Termux; Linux продолжает использовать свои текущие
инструменты Mason. Установка в новый каталог данных выполняется так:

```sh
npm ci --ignore-scripts --no-audit --no-fund --prefix /путь/к/данным/nvim/tools
```

Перед этим в каталог `tools` нужно скопировать оба package-файла из репозитория.
Команда не устанавливает Ansible-роли или коллекции. Автоматический запуск
`ansible-lint` настроен с аргументом `--offline`.

## Проверки

Проверки модулей не загружают Lazy и не устанавливают зависимости:

```sh
nvim --headless -u NONE -i NONE -l tests/check_platform.lua
nvim --headless -u NONE -i NONE -l tests/check_yaml_block_indent.lua
```

Полная проверка выполняется только с отдельными каталогами `XDG_CONFIG_HOME`,
`XDG_DATA_HOME`, `XDG_STATE_HOME` и `XDG_CACHE_HOME`, с подготовленными плагинами.
Переменная `NVIM_UNIVERSAL_TEST=1` запрещает автоматическую установку инструментов
Mason, парсеров и Codex. Набор проверок интерфейса — `scripts/check_universal.lua`;
проверка подключения языковых серверов — `scripts/check_lsp.lua`, которой также
нужна переменная `NVIM_TEST_PROJECT` с путём к тестовому проекту.

Эти скрипты создают и закрывают окна и тестовые терминалы. Их нельзя вызывать
в рабочем процессе Neovim с пользовательскими буферами.

## Резервирование и развёртывание

Перед заменой рабочей конфигурации сохраняются конфигурация, каталог данных,
состояние, кэши и несохранённые буферы. Архивы телефона передаются в WSL
потоком. Архивы и выгрузки буферов могут содержать чувствительные данные:
каталог резервной копии имеет режим `0700` и исключён из Git.

Замена каталогов выполняется только после проверки архива, тестирования
подготовленной сборки и подтверждения списка путей. Версии коммита и результаты
контрольных сумм фиксируются в журнале развёртывания.

Для подготовки нового набора инструментов непосредственно в Termux есть
`scripts/prepare_termux_tools.sh`. Его запускают явно с новым, ещё не
существующим каталогом `tools`. Скрипт отказывается перезаписывать существующий
каталог, ставит зафиксированные Node.js-зависимости и распаковывает Android-пакеты
Codex и Helm LS из репозитория Termux. Установленные системные пакеты при этом
не заменяются. Журналы остаются в системном временном каталоге Termux.

## Текущая проверка

- Изолированная сборка WSL, Neovim 0.11.5: запуск и общие функции проверены.
- В Linux-профиле с копией существующих Mason-пакетов проверены реальное
  подключение и инициализация `lua_ls`, `yamlls`, `ansiblels`, `basedpyright`.
- Termux-профиль дополнительно запущен на WSL с имитацией признака платформы:
  проверено отключение Mason и выбор Lua-движка blink.cmp. Это не заменяет
  запуск на Android.
- Нативная сборка на телефоне ARM64 с Neovim 0.12.3 проверена: полный запуск,
  Node.js LSP, сниппеты, YAML, выбор буферов, Markdown и парсеры.
- На обоих устройствах проверены настоящие клавиши F7/F8, Alt-z из терминала,
  Ctrl-k и выбор по метке Hop через `Пробел b b`.
- Скрипт установки инструментов повторно выполнен с нуля в новом каталоге.
  Проверен запуск Android-бинарника Codex 0.165.0.

## Совместимость Neovim 0.12

Закреплённый Tree-sitter использует прежний формат захватов — один TSNode вместо
списка. `lua/treesitter_compat.lua` адаптирует регистрацию старых предикатов и
директив, а также подготовленные совпадения для текстовых объектов. Адаптер
подключается до потребителей запросов; на Neovim 0.11 он ничего не меняет.
Проверены Markdown-инъекции, получение захватов и переход к следующей функции.
Установленные плагины и `lazy-lock.json` не редактировались.

На Neovim 0.12 AstroLSP ещё может выводить предупреждение об устаревшем API
codelens. Проверки подключения LSP проходят; это предупреждение не является
ошибкой запуска. Переход на новую основную версию AstroNvim остаётся отдельной задачей.

## Ограничения Termux

Закреплённый GitHub Copilot language server на Android не запускается: для его
нативного `vscode-policy-watcher` в дистрибутиве нет Android-бинарника. Поэтому
`copilot.lua` отключён только в Termux. В Linux он сохранён; обычные LSP-подсказки
и отдельная панель Codex доступны на телефоне. Библиотеки контроля политик не
подменяются заглушками. Авторизация учётной записи Codex выполняется пользователем;
проверка сборки ограничивается запуском CLI, а не отправкой запросов модели.

Необязательные серверы, отсутствующие в PATH телефона, не включаются. В частности,
для Terraform LS и Marksman здесь нет принудительной установки стороннего
Linux-бинарника. Подсветка Terraform и рендер Markdown работают независимо от них.
