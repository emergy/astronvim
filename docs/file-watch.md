# Автоматическое обновление открытых файлов

`lua/file_watch.lua` использует `vim.uv.new_fs_event()`: на Linux, WSL,
Termux и Nix-on-Droid события поступают через inotify. Дополнительного плагина
и постоянного опроса нет. Одно наблюдение создаётся на каталог загруженных
файлов; всё дерево проекта рекурсивно не просматривается.

Наблюдается каталог, поэтому сохранение через временный файл с последующим
rename не привязывает наблюдение к старому inode. Для символьных ссылок
наблюдаются также имя и каталог фактического файла.

События для нужных файлов объединяются в течение 60 мс одноразовым таймером.
При простое таймер не работает, файлы не проверяются. События соседних,
не загруженных файлов отбрасываются по имени. Обычное перечитывание выполняет
штатный `checktime` с учётом `autoread`; появившийся ранее отсутствовавший
файл перечитывается командой `edit` без принудительного сброса правок.

Обновляются также скрытые буферы и редакторские окна при активном терминальном
вводе. Фокус и раскладка окон сохраняются. В командной строке проверка
откладывается до `CmdlineLeave`, без повторного опроса по таймеру.

Несохранённые изменения в буфере сохраняются. При внешнем изменении такого
файла появляется одно предупреждение до следующего сохранения/перечитывания.
Удаление файла оставляет текст в буфере; наблюдение продолжает ждать его
восстановления. `noautoread` отключает наблюдение для соответствующих буферов.

Терминалы, URI, буферы `acwrite` и Ansible Vault исключены: они используют
собственные обработчики чтения. При выгрузке буфера его наблюдения освобождаются,
при выходе Neovim закрываются все оставшиеся handles.

Файловая система должна доставлять события ОС. Некоторые сетевые и проброшенные
каталоги, в частности изменения со стороны Windows на отдельных WSL-монтах,
могут их не передавать. При ошибке создания наблюдения выводится предупреждение;
периодический polling автоматически не включается. Штатная проверка при
возвращении фокуса в AstroNvim остаётся доступной.

Диагностика: `:lua vim.print(require("file_watch").stats())` показывает число
буферов, наблюдаемых каталогов и вызовов перечитывания. Для остановки в текущем
процессе: `:lua require("file_watch").stop()`; для повторного запуска — `setup()`.

Проверки на синтетических файлах:

```bash
nvim --headless -u NONE -i NONE -l tests/check_file_watch.lua
```

`tests/check_file_watch_ui.py` проверяет полную конфигурацию и настоящий PTY:
изменения выполняются отдельным процессом при активном терминальном вводе.
Запускать с отдельными XDG-каталогами и `NVIM_UNIVERSAL_TEST=1`, как описано
в `docs/universal.md`.
