# Автоматическое редактирование Ansible Vault

Существующий файл с первой строкой `$ANSIBLE_VAULT;…` автоматически открывается
расшифрованным. Обычные YAML-файлы и отдельные блоки `!vault` эта интеграция
не преобразует. Новые зависимости и плагины не устанавливаются.

Откройте файл привычным способом — аргументом `nvim`, через Neo-tree или `:edit`.
Редактируйте как текст и сохраняйте обычным `:write` / `:wq`.
В Neo-tree целиком зашифрованный файл обозначается жёлтым замком вместо
иконки типа файла. Значок определяется по заголовку на диске, без расшифровки,
и остаётся замком, когда в редакторе открыт расшифрованный буфер. Проверка
заголовка кешируется до изменения метаданных файла; отдельные `!vault`-значения
в обычном YAML этой иконкой не помечаются.
В буфере остаётся открытый текст, на диске — зашифрованный файл.

## Окружение Ansible

Исполняется `ansible-vault` из PATH Neovim. Настройки паролей и источников
Vault ID берёт сам Ansible: `ANSIBLE_CONFIG`, `ANSIBLE_VAULT_PASSWORD_FILE`,
`ANSIBLE_VAULT_IDENTITY_LIST`, `ansible.cfg` и остальные штатные настройки.
Каталог процесса фиксируется при открытии файла: последующий переход `:cd`
не переключает конфигурацию проекта при сохранении. Для смены проекта/настроек
можно изменить окружение и перечитать файл через `:edit!`.

Если в заголовке есть метка Vault ID, она сохраняется при шифровании, как при
`ansible-vault edit`. Пароли для неё по-прежнему разрешает Ansible; в настройках
Neovim отдельного списка ID и паролей нет. Для файла без метки выбор делает
Ansible. При нескольких ID может потребоваться штатная настройка
`ANSIBLE_VAULT_ENCRYPT_IDENTITY` / `vault_encrypt_identity`.

Интерактивного запроса пароля нет. Если настроенных источников недостаточно,
ошибка Ansible показывается в редакторе, шифротекст остаётся в буфере только
для чтения. После исправления окружения выполните `:edit!`.

## Сохранение и защита данных

Расшифрование и шифрование используют stdin/stdout; открытый текст не передаётся
в аргументах команды и не сохраняется во временный файл. Для Vault-буфера
отключены swap, постоянный undo и modeline. Буфер имеет тип `acwrite`:
обычный механизм записи/backup Neovim для него не используется. Стандартная
политика установленного Copilot не подключается к такому типу буфера.
Плагины и команды, которым пользователь явно передаёт текст буфера, имеют
доступ к нему как к обычному тексту.

Перед сохранением проверяется, что текущие источники паролей всё ещё позволяют
расшифровать исходник. Только после успешного шифрования новый шифротекст
записывается во временный файл рядом с назначением и атомарно заменяет исходный.
Временный файл содержит исключительно шифротекст. Сохраняются права и группа,
симлинк остаётся симлинком. Изменение файла другим процессом обнаруживается
сравнением исходного шифротекста перед заменой.

При ошибке буфер остаётся изменённым, а исходный файл не перезаписывается.
Файлы другого владельца и с несколькими жёсткими ссылками не сохраняются.
Запись под другим именем, диапазона строк и дописывание через `:write >>`
запрещены, чтобы они не обходили шифрование. Поддерживаются текстовые файлы,
включая UTF-8 BOM, LF/CRLF и отсутствие завершающего перевода строки;
двоичное содержимое не открывается для редактирования.

## Проверки

Проверка отдельного компонента с реальным `ansible-vault`:

```sh
nvim --headless -u NONE -i NONE -l tests/check_ansible_vault.lua
```

Проверка с установленной полной конфигурацией, без автоматической установки
инструментов:

```sh
NVIM_UNIVERSAL_TEST=1 nvim --headless -i NONE \
  '+luafile tests/check_ansible_vault.lua' '+qa!'
```

Тесты используют только синтетические пароли и данные в игнорируемом `.tmp/`.
Проверены открытие/сохранение, env и конфигурация проекта, Vault ID,
неверные источники паролей, внешние изменения, запрет экспорта, права,
симлинки, LF/CRLF и отсутствие постоянного undo и plaintext-резервных копий.
