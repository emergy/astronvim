# Nterm: Neovim как отдельный терминал

Запуск: `nterm`, либо `~/.config/nvim/scripts/nterm`.
`nterm --cwd /путь/к/проекту` запускает терминал в выбранном каталоге.
Другой вариант: `nvim --noplugin -i NONE --cmd 'let g:nterm_mode=1'`.

Это отдельная точка входа: Lazy, AstroNvim, LSP, Mason, Neo-tree,
ToggleTerm и обработчики файлов не запускаются. Hop загружается только при
первом `Space j` из уже установленного каталога плагина. Автоустановки нет.
Обычные `nvim`/`vim`, включая запущенные внутри Bash, используют обычный профиль.
В Nix команда `nterm` также описана в `nix/launcher/flake.nix`.

## Автозапуск на телефоне

В `.bashrc` Termux и Launcher подключается
`~/.config/nvim/terminal/autostart.bash`. Каждая новая интерактивная сессия
приложения с настоящим TTY открывает Nterm. После выхода остаётся обычный Bash;
повторное чтение `.bashrc` или запуск дочернего Bash Nterm снова не открывает.
SSH, терминалы внутри Neovim, tmux/screen и неинтерактивные команды пропускаются.
Профиль WSL автоматически не подключается.

`NTERM_ACTIVE=1` отмечает дерево процессов Nterm, включая ручной запуск и
вложенные оболочки; это не включает терминальный профиль у вложенного `nvim`.
При отсутствии команды или ошибке её запуска остаётся обычный Bash.
Для обхода автозапуска: `NTERM_AUTOSTART=0 bash`; для аварийной оболочки
без чтения настроек: `bash --noprofile --norc`.
Проверка условий: `python3 tests/check_nterm_autostart.py`.

## Уровни клавиатуры

Внешний слой резервирует **Ctrl+Space**. Один раз — перейти в его Normal mode;
два раза — отправить Ctrl+Space приложению внутри и вернуться к вводу.
Внизу виден индикатор `NTERM NORMAL` или `NTERM ВВОД`.

Остальные терминальные сочетания доходят до Bash, SSH и вложенного Vim.
В частности, Esc, Alt+z и стандартное `Ctrl+\ → Ctrl+n` вложенного Vim
обрабатываются внутри. Сам внешний слой управляется через Ctrl+Space.
Например, обычный `Space j` в удалённом Vim работает в нём, а
**Ctrl+Space → Space j** вызывает внешний Hop по терминальной истории.

Команды после перехода во внешний Normal mode:

| Клавиши | Действие |
|---|---|
| `i` / `a` | Вернуться к терминальному вводу |
| `/`, `?`, `n`, `N` | Обычный поиск по выводу |
| `v`, `V`, `Ctrl+v`, затем `y` | Выделить и скопировать в системный clipboard через OSC52 |
| `Space j` | Перейти к строке по метке Hop |
| `Space e` | Редактировать выделение или текущую строку как команду |
| `Space tn` | Новая вкладка с Bash |
| `Space th` / `Space tv` | Новый Bash в горизонтальном / вертикальном split |
| `Ctrl+w h/j/k/l` | Перейти между панелями |
| `Space t[` / `Space t]` | Предыдущая / следующая вкладка |
| `Space 1…9` / `Space 0` | Вкладка по порядку; 0 означает десятую |
| `Space tc` | Закрыть текущую панель и её Bash |
| `Space tq` | Выйти из Nterm |
| `Space ?` | Справка |

Clipboard использует тот же OSC52-механизм, что основная сборка; терминальное
приложение должно разрешать его. Системный clipboard автоматически не читается.
История прокрутки — 100000 строк на панель. Новые панели наследуют каталог
активного Bash. Вкладки и splits создаются встроенными окнами Neovim.

## Редактирование и выполнение команд

1. Ctrl+Space, затем найти нужный вывод; выделить часть через `v`/`V`.
2. `Space e` открывает временный редактор с точным выделенным текстом.
3. Исправить команду, при необходимости удалить приглашение shell/строки лога.
4. `:wq` сохраняет команду для выполнения и запускает её; `:q!` отменяет.

Без выделения `Space e` берёт текущую строку. Кроме того, **Ctrl+x Ctrl+e
в приглашении Bash** открывает этот же редактор с текущей строкой Readline.
Черновик поддерживает многострочные команды. `:w` отдельно помечает черновик
сохранённым в памяти; закрытие через `:q`/`:q!` команду не выполняет.

Readline принимает результат как обычную интерактивную команду в **том же Bash**:
сохраняются переменные, функции, aliases и текущий каталог; вывод идёт в ту же
панель. Работают обычные правила Bash history, включая HISTCONTROL/HISTIGNORE.
Дополнительная история переданных команд сохраняется в
`stdpath('state')/nterm/commands.jsonl` с правами 0600; каталог — 0700.

Запуск разрешён только в собственном приглашении Bash. Во время SSH,
вложенного Vim, `read`, `sleep` или другой команды черновик можно редактировать,
но выполнить его можно после возвращения к приглашению. Текст в активное
приложение не подставляется. Для выполнения на удалённом хосте используется
его собственный редактор строки/Readline, без установки внешних hooks туда.

Временные IPC-файлы находятся в отдельном каталоге 0700 под TMPDIR; файлы —
0600. Они удаляются при завершении Nterm. Черновик не использует swap,
постоянный undo или backup. При исчезновении Bash запуск блокируется.

## Проверки

`python3 tests/check_nterm.py` создаёт отдельный PTY и тестовый Bash rc-файл.
Проверяются отсутствие Lazy/ToggleTerm, ленивый Hop, реальные вкладки/splits,
контекст Bash и его history, многострочный черновик, отмена, занятая сессия,
Ctrl+x Ctrl+e, передача байтов, настоящий вложенный Neovim, выделение,
OSC52 и освобождение временных файлов. SSH-аккаунты и рабочие процессы
пользователя в этой проверке не используются.

В Termux при повторных RPC-запусках тестовая обвязка воспроизвела abort
CPython 3.13 в `PyConfig_Clear` с повреждением Scudo heap. Для неё отключён
`subprocess._USE_VFORK`; повторный прогон завершился с кодом 0. Механизм
отключения описан в [документации Python](https://docs.python.org/3.13/library/subprocess.html#disabling-use-of-vfork-or-posix-spawn).
Рабочий профиль использует Lua/Bash и Python не запускает.
