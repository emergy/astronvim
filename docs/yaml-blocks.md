# Подсветка языков внутри многострочного YAML

Комментарий с именем языка после индикатора скаляра выбирает подсветку его тела:

```yaml
steps:
  - | # sh
    cat <<'EOF'
    example
    EOF
  - |- # py
    def example():
      return 42

script: >- # python
  print("hello")
```

Поддерживаются `|`, `|-`, `>`, `>-` как в значениях ключей, так и в элементах
списков. Между индикатором и `#` нужен пробел. В комментарии указывается только
имя языка; пояснение с дополнительными словами считается обычным комментарием.

Короткие имена: `sh`/`bash`, `py`/`python`, `js`/`javascript`,
`ts`/`typescript`. Можно использовать и полное имя другого доступного языка,
например `lua`, `json` или `sql`.

В обычном YAML и YAML/Ansible с активным Tree-sitter используется установленный
парсер выбранного языка. В режиме Vim syntax, в том числе в `yaml.jinja2`,
подключается соответствующий `syntax/<язык>.vim` из runtime. Если нужной
подсветки нет, блок остаётся с обычной YAML-подсветкой. Метки не запускают
установку парсеров или плагинов.

В шаблонах сохраняются выражения, фильтры, комментарии и управляющие блоки
Jinja внутри встроенного языка. Добавление, изменение и удаление метки
применяются при редактировании; файл перечитывать не требуется.

Явная метка важнее автоматической shell-подсветки ключей `script`, `run` и
подобных: `script: | # py` подсвечивается как Python. Без меток штатные
инъекции GitHub Actions, GitLab CI, Taskfile и Prometheus сохраняются.

Подсветка не меняет значение YAML: `>` по-прежнему складывает строки,
а `|` сохраняет переносы.

## Настройки и проверки

- `queries/yaml/injections.scm` — инъекции Tree-sitter. Сохраняет штатные
  правила закреплённого nvim-treesitter; при обновлении плагина сверять их
  с upstream.
- `lua/yaml_blocks.lua` — границы инъекций и подключение Vim syntax только
  для языков, чьи метки встречаются в буфере. Изменения отслеживаются через
  `on_lines`, без постоянного таймера или фонового процесса.
- `after/syntax/yaml.lua`, `syntax/yaml_block_include.vim` — подключение
  вложенной подсветки и Jinja в одной области syntax.

```sh
nvim --headless -u NONE -i NONE -l tests/check_yaml_blocks.lua
nvim --headless -u NONE -i NONE -l tests/check_jinja_templates.lua
nvim --headless -u NONE -i NONE -l tests/check_yaml_block_indent.lua
```

Проверяются четыре индикатора, ключи и списки, независимые соседние языки,
приоритет явной метки, heredoc, длинные блоки, пустые строки, Jinja,
отсутствующие языки, реальные дочерние парсеры и изменение меток.
