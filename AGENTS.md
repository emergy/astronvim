# Инструкции агентам для конфигурации Neovim

## Контекст пользователя

- Общаться по-русски.
- Пользователь работает в терминальном AstroNvim и привыкает к нему после VS Code.
  Не предлагать команды VS Code для применения настроек Neovim.
- Используются WSL и devcontainers. Уточнять, какой процесс Neovim и какая
  конфигурация задействованы, если наблюдения не совпадают с файлами на диске.
- Причина перехода: высокое потребление памяти несколькими экземплярами VS Code
  и devcontainers. Не добавлять фоновые сервисы и плагины без необходимости.
- Подробные локальные знания и проверка: [.agents/KNOWLEDGE.md](.agents/KNOWLEDGE.md).

## Работа с конфигурацией

- Здесь отдельный Git-репозиторий. В нём есть незакоммиченные пользовательские
  изменения; перед работой смотреть `git status --short` и нужные диффы.
- Не откатывать, не перезаписывать и не включать чужие изменения в свои коммиты.
- После каждого завершённого и проверенного изменения сразу создавать Git-коммит
  со своими правками, без отдельного запроса пользователя. Делать это до отчёта
  о завершении работы; указывать хеш коммита в отчёте.
- Если проверка не прошла, сначала исправить проблему. Не коммитить чужие
  изменения или незавершённую работу ради чистого рабочего дерева.
- Без запроса не обновлять плагины или `lazy-lock.json`.
- Менять пользовательские настройки в этом репозитории, а не установленные
  плагины в `~/.local/share/nvim/lazy/` и не runtime в `/opt/nvim*/`.
- Перед загрузкой файла проверять, нет ли в начале отключающей строки
  `if true then return {} end`: наличие настроек ниже не означает их применение.
- Учитывать порядок загрузки Lazy.nvim, FileType и Tree-sitter.
  Автокоманда FileType может быть перезаписана более поздней загрузкой плагина.
- Не запускать установки/обновления Lazy, Mason, парсеров и Ansible-зависимостей
  как побочный эффект проверки. Для ограниченных проверок использовать
  `nvim --headless -u NONE -i NONE` и явно нужные установленные плагины.
- Для изменений Lua проверять синтаксис и затронутое поведение. Различать
  проверку отдельных компонентов и полноценный запуск всей конфигурации.
- Для применения постоянных настроек обычно достаточно перезапуска Neovim.
  Команды для текущего буфера давать отдельно и с точным назначением.

## YAML: действующий контракт

Пользователь предпочитает вложенные списки с отступом 2 пробела:

```yaml
list:
  - 1
  - 2
```

- Поддерживать как `yaml`, так и `yaml.ansible`.
- Tree-sitter indentation для языка `yaml` выключен через
  `lua/plugins/treesitter.lua`: `indent = { disable = { "yaml" } }`.
  Подсветка Tree-sitter при этом не отключается.
- Не возвращать автокоманду, которая просто очищает `indentexpr`: ранее она
  не предотвращала последующее назначение `nvim_treesitter#indent()`.
- В `after/indent/yaml.lua` и `after/indent/ansible.lua` сохранён обход с удалением
  триггеров `0-`, `-`, `<:>`, но в текущем состоянии он закомментирован.
  Не включать его автоматически: сначала проверить действующий обработчик
  и исходные примеры. При вводе дефиса и двоеточия отступ не должен прыгать.
- `.agents/check-yaml-indent.lua` пока ожидает активный обход и на этом падает;
  не трактовать это как доказательство поломки текущей конфигурации.
- При жалобе сначала получить из проблемного буфера:
  `:verbose setlocal filetype? indentexpr? indentkeys? shiftwidth?`.
  Не считать заранее виновным форматтер, YAML-плагин или стиль списков.
- Штатные функции `GetYAMLIndent` и `GetAnsibleIndent` уже поддерживают нужный
  стиль. После исправления пользователь подтвердил нормальную работу.

## Терминалы

- Используется ToggleTerm; F8 открывает выбор терминалов через `terminal_sessions`.
- В `lua/plugins/toggleterm.lua` задано `auto_scroll = false`: принудительный
  переход вниз при каждом выводе отключён. Штатный Neovim следует за выводом,
  когда курсор находится на последней строке; просмотр истории не прерывается.
- В `lua/plugins/astrocore.lua` задано `scrollback = 100000` — максимум текущей
  версии Neovim. Это число строк истории на терминал, а не неограниченный лог.
- Не возвращать безусловную прокрутку и не менять выбор/названия терминалов
  при исправлении поведения просмотра вывода.
- Проверка с настоящим PTY: `.agents/check-terminal.lua`.

## Локальные артефакты

- `.agents/` — знания, диагностика и вспомогательные проверки; не хранить секреты.
- `.tmp/`, `.reports/`, `.backups/`, `.operation-manifests/` — временные файлы,
  отчёты, резервные копии и журналы операций; не класть их рядом с Lua-настройками.
- Сохранять подтверждённые причины и результаты в локальных заметках, отделяя их
  от гипотез. Актуальное поведение в пользовательском буфере важнее старых заметок.
