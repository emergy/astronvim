# Оценка обновления AstroNvim 5.3 → 6.1.1

Проверено 2026-10-27. Обновление не выполнялось. Это статический аудит
конфигурации и исходников релиза, не заключение по результатам запуска v6.

## Вывод

Непосредственная замена `version = "^5"` на v6 без миграции небезопасна:
обнаружены две конкретные несовместимости в настройках YAML и Ansible LSP.
Контролируемое обновление в отдельном окружении реалистично. Срочной причины
обновлять рабочий редактор по результатам этого аудита нет.

## Проверенное исходное состояние

- Конфигурация: `/home/emergy/.config/nvim`, HEAD `f56cc62` (Agent).
- Установленный AstroNvim: точный тег `v5.3`, commit
  `55a2b084eabe880c4ffa377f82bb972caec57e09`.
- `lua/lazy_setup.lua`: `version = "^5"`, стандартное закрепление основных
  плагинов включается при отслеживании версий. Этот диапазон сам не обновится до v6.
- Neovim: v0.11.5. Соответствует требованию AstroNvim 6.1.1: Neovim 0.11+.
- nvim-treesitter: ветка master, commit `42fc28ba918343ebfd5565147a42a26580579482`.
- В `after/indent/yaml.lua` и `ansible.lua` удаление триггеров сейчас
  закомментировано. Не включать его повторно под видом миграции.
- C compiler найден; tree-sitter CLI не найден в PATH и обычном Mason bin.
  На этапе миграции проверить требования CLI/версии для закреплённого парсера.

## Что изменилось

Основная перестройка произошла в v6.0, а не в патче v6.1.1:

- LSP переведён на `vim.lsp.config`/`vim.lsp.enable`, AstroLSP v4 и
  mason-lspconfig v2.
- nvim-treesitter переведён с master на переписанную main; функции подсветки,
  отступов и textobjects настраиваются через `AstroCore.opts.treesitter`.
- Настройки float-границ используют `winborder`.
- vim-illuminate заменён на snacks.words; neoconf удалён из стандартного набора.
- Новые возможности включают настройку LSP через `lsp/<server>.lua`, автоматическую
  установку парсеров и диагностику workspace (последняя требует Neovim 0.12+).
- v6.1 добавляет `gI` для перехода к реализации; сочетание Ctrl+Backspace для
  multicursor относится к Neovim 0.13.
- v6.1.1 от 2026-10-16: динамическая регистрация LSP file operations,
  исправление зависимости window-picker у Neo-tree, закрепление smart-splits на v2.
- Между v6.0 и v6.1.1 также исправлялись запуск, операции с буферами, интеграции
  терминалов и совместимость с разными версиями Neovim. Эти исправления не дают
  доказательств заметного снижения потребления памяти для данного пользователя.

## Риски конкретной конфигурации

### 1. Отключение YAML indentation перестанет действовать

Текущий `lua/plugins/treesitter.lua` задаёт старый `opts.indent.disable`.
В v6.1.1 спецификация nvim-treesitter не вызывает старый configs.setup;
AstroCore включает indentation отдельно, по умолчанию true. Это создаёт
конкретный риск возврата скачков отступа, которые пользователь недавно устранил.

Предложение для отдельного окружения v6 (сейчас НЕ применено):

```lua
return {
  "AstroNvim/astrocore",
  opts = {
    treesitter = {
      ensure_installed = { "lua", "vim" },
      indent = function(lang) return lang ~= "yaml" end,
    },
  },
}
```

У AstroCore v3.1.2 свойство indent поддерживает функцию `(lang, bufnr)`.
Перенести ensure_installed из старой спецификации, убрать старый блок indent.
Сохранить решение пользователя о включённых триггерах ввода.

### 2. root_dir у ansiblels использует старую сигнатуру

`lua/plugins/ansible.lua` передаёт результат `lspconfig.util.root_pattern(...)`
как root_dir. Старый интерфейс ожидает имя файла и возвращает путь. Новый
ожидает `(bufnr, on_dir)` и должен вызвать `on_dir(root)`.
AstroLSP v4 передаёт config напрямую в `vim.lsp.config`.

Проверка вызовом текущей старой функции с новой сигнатурой: исключения нет,
но callback не вызван. По контракту Neovim это не активирует LSP для буфера.
Следовательно, «нет ошибки при старте» ещё не означает рабочий Ansible LSP.

Миграция: callback с `vim.fs.root(bufnr, markers)` и `on_dir`, либо корректная
настройка root_markers с учётом наследуемого root_dir у ansiblels. Проверить
выбор ближайшего корня по `.ansible-lint`, `ansible.cfg`, `.git` и запуск из
вложенного каталога. В рабочем файле сейчас ничего не менялось.

### 3. Остальные настройки

- `.neoconf.json` содержит настройки lua_ls; в v6 они не будут читаться штатным
  набором плагинов. Если поведение нужно сохранить, перенести в конфигурацию LSP.
- `lua/plugins/astrolsp.lua` отключён первой строкой: старые примеры handlers
  внутри не являются действующими несовместимостями.
- ToggleTerm остаётся в диапазоне v2. Наш auto_scroll=false и логика F8 не
  требуют очевидной миграции по исходникам; runtime-проверка всё равно нужна.
- scrollback=100000, D → чёрный регистр и OSC 52 используют базовые API Neovim;
  явных препятствий переходу не найдено.
- render-markdown и AstroCommunity-пакеты требуют совместной проверки с новым
  Tree-sitter/LSP. Отсутствие найденной ошибки не является доказательством
  совместимости всех сторонних плагинов.
- v6.1.1 содержит отдельное закрепление Tree-sitter для Neovim <0.12.
  Не отключать pin_plugins и не обновлять его произвольно до HEAD main.

## Безопасная последовательность миграции

1. Создать отдельную конфигурацию и отдельные data/state/cache через
   `NVIM_APPNAME=astronvim_v6_trial`; скопировать текущие незакоммиченные изменения,
   если они появятся, а не только HEAD. Рабочие каталоги nvim не переименовывать.
2. В тестовой конфигурации закрепить AstroNvim ровно на `v6.1.1` на время проверки.
   Не переиспользовать рабочие plugin directories и Mason через симлинки.
3. Выполнить две указанные миграции и осознанно перенести нужные neoconf-настройки.
4. Установить тестовые плагины/инструменты только в изолированное окружение.
   Не запускать Ansible Galaxy и не применять playbook к нодам для проверки редактора.
5. Проверить старт, YAML/Ansible из разных каталогов, запуск и диагностику ansiblels,
   отсутствие второго ansible-lint, подсветку и Markdown, F8/терминалы,
   сохранение истории, возврат слежения, OSC 52, русскую раскладку и D.
6. Проверить полную интерактивную сессию. Лишь после этого обсуждать перенос
   в основной профиль и точный план возврата, сохраняющий версии зависимостей.

Установка отдельного окружения в рамках этого аудита не выполнялась.

- Проверен контракт root_dir по исходникам Neovim v0.11.5 и пробным вызовом.
