# Локальные знания об AstroNvim

Сверено 2026-10-27. Это заметки о конкретной конфигурации, не универсальные
утверждения о всех версиях Neovim и плагинов.

## Окружение и точки входа

- Репозиторий: `/home/emergy/.config/nvim`.
- `/usr/bin/nvim` указывает на `/opt/nvim-linux-x86_64/bin/nvim`.
- Штатный runtime: `/opt/nvim-linux-x86_64/share/nvim/runtime`.
- Установленные плагины: `~/.local/share/nvim/lazy/`.
- `init.lua` загружает Lazy.nvim, затем `lua/lazy_setup.lua` и `lua/polish.lua`.
  При отсутствии Lazy.nvim bootstrap клонирует его из сети: для диагностики
  без установки использовать `-u NONE`.
- `lua/community.lua` импортирует пакеты AstroCommunity, в том числе Ansible.
- `lua/plugins/astrocore.lua`: базовые опции, файловые типы и привязки клавиш.
- `lua/plugins/treesitter.lua`: настройки Tree-sitter; файл теперь активен.
- `lua/plugins/ansible.lua`: настройки ansiblels и отключение второго запуска
  ansible-lint через mason-null-ls. Это не общее отключение диагностики Ansible.
- `lua/polish.lua` содержит настройку буфера обмена OSC 52.
- Не использовать старый шаблонный README как описание текущего состояния.

## Ошибки отступов YAML: симптомы и установленная причина

1. После `o` ввод `-` сдвигал строку вложенного списка к внешнему уровню.
2. При переделке folded scalar в mapping ввод `:` перед существующим путём
   сдвигал `file` к уровню соседних ключей.
3. Первой гипотезой были встроенные YAML/Ansible indent-функции. Отключение
   триггеров было обходом, а не доказательством причины.
4. Пользователь предоставил фактический вывод из проблемного буфера:

```text
filetype=yaml
indentexpr=nvim_treesitter#indent()
indentkeys=!^F,o,O,0},0],<:>
shiftwidth=2
```

5. В AstroNvim Tree-sitter indentation включён по умолчанию. Старый локальный
   обработчик FileType, очищавший `indentexpr`, не обеспечивал нужного результата.
6. В `lua/plugins/treesitter.lua` включена пользовательская спецификация и добавлено
   `indent = { disable = { "yaml" } }`. Старый обработчик удалён из astrocore.
7. В `after/indent/yaml.lua` и `after/indent/ansible.lua` сохранено удаление
   триггеров `0-`, `-`, `<:>`.
8. После этих изменений пользователь сообщил: «теперь вроде нормально работает».

Не приписывать проблему выбору между вложенными и невложенными списками:
штатные indent-функции в проверенных версиях возвращают 2 для обоих элементов
списка `list:
  - 1
  - 2`.

## Диагностика и применение

В проблемном буфере:

```vim
:verbose setlocal filetype? indentexpr? indentkeys? shiftwidth?
```

Ожидаемые обработчики: `GetYAMLIndent(v:lnum)` для YAML,
`GetAnsibleIndent(v:lnum)` для Ansible YAML. `nvim_treesitter#indent()` здесь
быть не должен. Триггеры `0-`, `-`, `<:>` должны отсутствовать.

Постоянные настройки применяются после перезапуска Neovim. Для временного
отключения Tree-sitter indentation и перезагрузки правил текущего буфера:

```vim
:TSBufDisable indent
:filetype indent off
:filetype indent on
```

Для отключения только триггеров в текущем буфере:

```vim
:setlocal indentkeys-=0- indentkeys-=- indentkeys-=<:>
```

В YAML после `:` перед значением нужен пробел: `file: tasks/package_facts.yml`.
Промежуточная строка во время ввода может быть невалидна, но не должна терять
выбранный пользователем отступ.

## Воспроизводимая проверка без загрузки всего AstroNvim

```bash
nvim --headless -u NONE -i NONE -l ~/.config/nvim/.agents/check-yaml-indent.lua
```

Проверка использует уже установленные Tree-sitter и ansible-vim, загружает
локальную спецификацию Tree-sitter с запретом YAML indentation, проверяет оба
файловых типа, вложенные списки и ввод `:`/`-`. Не устанавливает плагины или
парсеры, не меняет пользовательские файлы. Это проверка компонентов;
окончательная проверка полной конфигурации — вывод из реального буфера и
поведение редактора пользователя.

## Терминал: прокрутка и история (2026-10-27)

Пользователь запускает длинные Ansible playbook в терминале и читает историю
во время выполнения. Нужно сохранять место просмотра; следить за выводом снова
после возврата курсора на последнюю строку (`G` в Normal mode).

В установленном ToggleTerm `Terminal:__make_output_handler` безусловно вызывает
`scroll_bottom()` на stdout/stderr, если `auto_scroll` включён. Значение по
умолчанию — true. В `lua/plugins/toggleterm.lua` добавлено `opts.auto_scroll = false`.
Это сохраняет встроенное следование Neovim по последней строке.

В `lua/plugins/astrocore.lua` добавлено `scrollback = 100000`. Штатный предел —
10000, максимальное поддерживаемое значение установленной версии — 100000.
Отброшенные ранее строки не восстанавливаются. Более длинный вывод нужно
сохранять отдельным логом; конечный буфер не гарантирует сохранение любого playbook.

Проверка без загрузки всего AstroNvim:

```bash
nvim --headless -u NONE -i NONE -l ~/.config/nvim/.agents/check-terminal.lua
```

Используется установленный ToggleTerm и настоящий PTY с Python-процессом.
Проверены сохранение более 10000 строк, неизменность курсора и верхней видимой
строки при новом выводе во время просмотра истории, возобновление слежения
после `G`. Для изоляции проверка подменяет только модуль выбора/названий
терминалов; полный запуск пользовательской конфигурации не проверяется.

Постоянные настройки применяются после перезапуска Neovim. Для существующих
ToggleTerm-терминалов временно можно выполнить:

```vim
:lua for _, t in ipairs(require("toggleterm.terminal").get_all()) do t.auto_scroll = false end
```

Для увеличения истории в текущем терминальном буфере: `:setlocal scrollback=100000`.

## Shift+D без копирования (2026-10-27)

В Normal mode `D` сопоставлен с `"_D` через `opts.mappings.n` в
`lua/plugins/astrocore.lua`. Удаляет от курсора до конца строки через чёрный
регистр, сохраняя регистры и буфер обмена. Остальные команды удаления не менялись.
Для немедленного применения в текущем Neovim: `:nnoremap D "_D`.

## Стартовый экран со шпаргалкой (2026-10-27)

## Neo-tree при запуске без аргументов (2026-10-27)

В init спецификации `lua/plugins/neo-tree.lua` добавлен одноразовый обработчик
`User VeryLazy`. Только при `argc(-1) == 0`, если текущий буфер — dashboard или
пустой немодифицированный обычный буфер, выполняется `neo-tree.command.execute`
с action=show, source=filesystem, position=left. Обработчик отложен до VeryLazy,
чтобы не мешать открытию Snacks dashboard на UIEnter. Фокус остаётся в основном
окне. При файле в аргументах обработчик не создаётся; сеанс или уже открытый
рабочий буфер не подменяется.

Проверка установленным Neo-tree с реальным созданием split:

```bash
nvim --headless -u NONE -i NONE -c 'luafile ~/.config/nvim/.agents/check-neotree-startup.lua' -c 'qa!'
nvim --headless -u NONE -i NONE ~/.config/nvim/AGENTS.md -c 'luafile ~/.config/nvim/.agents/check-neotree-startup.lua' -c 'qa!'
```

Оба сценария прошли; это изолированная проверка обработчика, не всей загрузки AstroNvim.

Памятка дополнена двумя группами Neo-tree: навигация и операции с файлами.
При проверке учитывать переопределения AstroNvim: h=parent_or_close,
l=child_or_open, Y=copy_selector, пробел не является toggle_node.
s открывает вертикальный split, S — горизонтальный. Проверена отрисовка
дополненной памятки при ширине 120 и 80 колонок.

Быстрые действия dashboard уплотнены: четыре строки по два действия при ширине
от 65 колонок, без растягивания клавиши к правому краю. В узком окне — один
столбец. Все восемь клавиш сохраняются через скрытые actionable items Snacks.
Neo-tree расширен блоками фильтров/поиска и сортировки/вида, сворачивания узлов,
смены источников и очистки очереди копирования. Реальная отрисовка и наличие
всех восьми buffer-local mappings проверены на ширинах 120, 80, 60 колонок.

видимость. Проверено реальное построение дерева каталога collections:
игнорируемый ansible_collections присутствует при hide_gitignored=true.
